# คำสั่งออกแบบ Mockup: AI Mode บนเว็บ (PC)

## เป้าหมาย

สร้างหน้า AI Mode สำหรับ MR.Zettascale ที่ใช้คุยและทำงานกับ AI ได้ต่อเนื่องบน PC ให้บทสนทนาเป็นจุดสนใจหลัก ผู้ใช้ต้องอ่านคำตอบ เลือกเครื่องมือ ตรวจผลลัพธ์ และพิมพ์ต่อได้โดยไม่ต้องจัดการหน้าต่างหลายชั้น ให้ความชัดเจนของขั้นตอนสำคัญกว่าการตกแต่ง

ออกแบบ **เฉพาะ PC ในรอบนี้** ใช้พื้นที่ตัวอย่างกว้างประมาณ 1280–1440 พิกเซลและสูงประมาณ 800–900 พิกเซล ยังไม่ต้องทำรูปแบบมือถือหรือกำหนดพฤติกรรมสำหรับจอสัมผัส

## ไฟล์ที่ต้องส่งมอบ

1. สร้าง `frontend/src/dev/mockups/activity-mode-ai-workspace-mockup.jsx` และ `export default` React component ที่เปิดดูได้โดยลำพัง ชื่อไฟล์ต้องตรงรูปแบบนี้เพื่อให้ระบบ preview ปัจจุบันค้นพบอัตโนมัติ แม้เนื้อหาจะเป็น AI Mode
2. ถ้าต้องใช้ CSS ให้สร้าง `frontend/src/dev/mockups/activity-mode-ai-workspace-mockup.css` แล้ว import จากไฟล์ JSX ใช้ชื่อคลาสที่ขึ้นต้นด้วย `ai-workspace-mockup-` เพื่อไม่ให้สไตล์ไปกระทบแอปจริง
3. ใช้ข้อมูลตัวอย่างและ React state ภายใน mockup เท่านั้น ห้ามเรียก backend, Gemini, Firebase, Telegram, Google Calendar หรือแก้ข้อมูลจริง ห้าม import component จากระบบ production เพื่อให้เปลี่ยนแบบได้อิสระ
4. ให้ mockup กดทดลองเส้นทางหลักได้จริงด้วย state จำลอง ไม่ส่งมอบเพียงภาพนิ่ง หากใช้ไอคอน ให้ใช้ SVG/องค์ประกอบใน JSX หรือไฟล์ asset ที่อยู่ในโปรเจกต์ ไม่พึ่งบริการภายนอก

## โครงสร้างหน้าที่ต้องออกแบบ

ให้เห็นว่า AI Mode เป็นหน้าหนึ่งของเว็บ T.i.M.E.S. ซึ่งเปิดจากเมนูหลักและกลับไปหน้าเดิมได้ ออกแบบพื้นที่ทำงานโดยมีส่วนต่อไปนี้ครบ แต่จัดตำแหน่งใหม่ได้ตามแนวคิดของคุณ

- **ตัวตนและการนำทาง:** แสดงชื่อ MR.Zettascale, สถานะ AI ที่เข้าใจง่าย, ปุ่มกลับ และปุ่มเริ่มแชทใหม่ แสดงโควต้าเฉพาะเมื่อเกี่ยวข้อง โดยไม่กินพื้นที่อ่านบทสนทนามาก
- **บทสนทนาหลัก:** แยกข้อความผู้ใช้กับคำตอบให้อ่านต่อเนื่อง แสดงที่มาของคำตอบอย่างกระชับ เช่น `AI`, `ข้อมูล/กฎในเว็บ`, `คำตอบสำเร็จรูป`, `AI · ปฏิทิน` รองรับคำตอบยาวและหลายข้อความโดยเลื่อนเฉพาะส่วนที่เหมาะสม
- **ช่องพิมพ์:** อยู่ในตำแหน่งที่เห็นและเข้าถึงได้ตลอดขณะอ่านแชท มีสวิตช์ `คุยอิสระ` และ `วางแผนกิจกรรม`, ช่องข้อความ, ปุ่มส่ง และสถานะส่งไม่ได้/กำลังส่ง ใช้ข้อความแนะนำที่ตรงกับโหมดที่เลือก
- **เครื่องมือ:** มีทางเข้าที่หาเจอง่ายแต่ไม่แสดงปุ่มจำนวนมากค้างบนหน้า ครอบคลุมดูตาราง, สรุปวันนี้, หาเวลาว่าง, สร้างกิจกรรม และคำถามหรือคำสั่งสำเร็จรูป เมื่อเปิดเครื่องมือแล้วต้องกลับมาอ่านแชทได้ง่าย
- **ผลลัพธ์ที่โต้ตอบได้:** แสดงคำถามติดตาม, ตัวเลือกช่วงเวลาว่าง, คำเตือนเวลาชน และร่างกิจกรรมที่เลือก/แก้ไขได้ ผลลัพธ์ต้องอยู่ใกล้ข้อความที่สร้างมัน
- **ข้อความ Telegram:** แยกจากบทสนทนา AI บนเว็บอย่างเห็นได้ชัด เช่น ส่วนพับเก็บได้ มีจำนวนข้อความและทางเข้าดูสำเนา ปุ่มเริ่มแชทใหม่ของ AI ต้องไม่สื่อว่าจะลบสำเนา Telegram ด้วย หากมีปุ่มส่ง Telegram ให้แยกความหมายจากปุ่มส่งหา AI ชัดเจน

## เส้นทางที่ต้องกดลองได้ใน mockup

1. เปิดหน้า AI Mode → อ่านข้อความต้อนรับ → พิมพ์คำถามทั่วไปใน `คุยอิสระ` → เห็นข้อความผู้ใช้ สถานะกำลังคิด และคำตอบจำลอง
2. เปิดเครื่องมือ → เลือกดูตารางหรือหาเวลาว่าง → เห็นคำตอบพร้อมที่มาของข้อมูล → เลือกหนึ่งช่วงเวลาได้
3. เลือกสร้างกิจกรรม → ตอบคำถามติดตาม → เห็นร่างที่มีชื่อ วัน เวลา และระยะเวลา → แก้ไขหรือยกเลิกได้ → กดยืนยันเพื่อจำลองการส่งไปขั้นตอนตรวจบันทึก
4. เริ่มแชทใหม่ → เห็นบทสนทนา AI เริ่มใหม่ แต่สำเนา Telegram จำลองยังอยู่
5. เปิดดูสำเนา Telegram แล้วพับกลับ โดยบทสนทนา AI หลักไม่ถูกแทนที่

**การสร้างกิจกรรมต้องมีขั้นตอนให้ผู้ใช้ตรวจและยืนยันก่อนบันทึกเสมอ** อย่าออกแบบให้คำตอบของ AI สร้างรายการในปฏิทินทันที

## สถานะตัวอย่างที่ต้องแสดง

เตรียมข้อมูลตัวอย่างที่สลับดูได้ภายใน mockup อย่างน้อย: หน้าเริ่มต้น, บทสนทนาที่มีหลายข้อความ, กำลังรอ AI, คำตอบยาว, เครื่องมือเปิดอยู่, ร่างกิจกรรมรอตรวจ, ไม่พบช่วงเวลาว่าง, ข้อผิดพลาด, และโควต้า AI หมดหรือยังไม่มีสิทธิ์ใช้ AI ให้แต่ละสถานะมีข้อความที่บอกผู้ใช้ว่าทำอะไรต่อได้

แสดงความสามารถตามจริงในตัวอย่าง: `คุยอิสระ` ใช้ AI และขณะนี้จำกัดสิทธิ์สำหรับนักพัฒนา; คำตอบข้อมูล T.i.M.E.S. บางกรณีมาจากกฎ/ข้อมูลที่ยืนยันแล้ว; การอ่านตารางและการร่างกิจกรรมใช้เครื่องมือเฉพาะ ขณะนี้ยังไม่มีเครื่องมือข่าวหรืออากาศสดใน AI Mode จึงอย่าออกแบบผลลัพธ์สดเหล่านั้นเป็นความสามารถที่ใช้งานแล้ว

## เกณฑ์ตรวจ mockup

- ผู้ใช้มองครั้งแรกแล้วรู้ว่าพิมพ์ตรงไหน ส่งให้ใคร และเปิดเครื่องมือตรงไหน
- แชทยังอ่านได้ขณะตรวจร่างหรือตัวเลือกเวลา โดยไม่ถูกหน้าต่างใหญ่บังทั้งหมด
- พื้นที่ PC ไม่รกจากเมนูหรือปุ่มที่ยังไม่เกี่ยวกับงานปัจจุบัน
- ไม่มีการเลื่อนแนวนอนที่ความกว้าง PC ที่กำหนด และช่องพิมพ์กับปุ่มส่งไม่หายจากพื้นที่ใช้งาน
- ทุกปุ่มที่แสดงใน mockup มีผลจำลองที่สอดคล้องกับชื่อปุ่ม หรือแสดงชัดว่าเป็นตัวอย่างที่ยังไม่ทำงาน
- ใช้ข้อความภาษาไทยที่อ่านง่ายและให้ความหมายตรงกับพฤติกรรมจริง

เปิดดูตัวอย่างด้วย `npm run dev` ใน `frontend` แล้วกด `Ctrl + Alt + W` บนหน้าเว็บขณะที่ไม่ได้โฟกัสช่องพิมพ์ จากนั้นเลือก mockup นี้ในตัวเลือกของหน้า preview

ไฟล์นี้เป็นโจทย์ออกแบบ ยังไม่ต้องแก้หน้า AI Mode ใน production เมื่อได้ mockup แล้วจึงค่อยนำแบบที่เลือกไปเชื่อมกับ state และ backend ที่มีอยู่
