# MR.Zettascale — แผนการพัฒนา (Development Plan)

### เป้าหมายของผลิตภัณฑ์ (Product Goal)
* **MR.Zettascale** คือผู้ช่วยวางแผนการทำงานบนเว็บภายใน Activity Mode ของระบบ T.i.M.E.S.
* หน้าที่หลักประการแรกคือการแปลงคำขอภาษาธรรมชาติ (Natural-language request) สั้นๆ ให้เป็นร่างกิจกรรม (Activity draft) ที่ปลอดภัยและเปิดให้ผู้ใช้ตรวจสอบได้
* ระบบผู้ช่วยต้องไม่แอบสร้าง แก้ไข หรือลบข้อมูลในปฏิทินเองโดยเด็ดขาด ผู้ใช้งานจะต้องเป็นผู้ตรวจสอบร่างกิจกรรมเสมอ สามารถแก้ไขฟิลด์ข้อมูลด้วยตนเองในช่องแชท และต้องกดปุ่ม **Confirm** (ยืนยัน) อย่างชัดเจนก่อนที่กิจกรรมจะถูกสร้างลงปฏิทินจริง

### ประสบการณ์หลักของผู้ใช้ (Primary Experience)
* ผู้ใช้ควรได้รับร่างกิจกรรมที่พร้อมใช้งานภายใน 1 ถึง 3 ข้อความโต้ตอบ

**ตัวอย่างการทำงาน:**
* คำขอผู้ใช้: *"พรุ่งนี้หลังเลิกงานไปออกกำลังกาย"*
* MR.Zettascale จะเสนอชื่อกิจกรรม วันที่ เวลาเริ่มต้น/สิ้นสุด และหมวดหมู่ตัวเลือก พร้อมระบุค่าทั้งหมดที่ระบบสันนิษฐานขึ้นมาอย่างชัดเจน
* ผู้ใช้สามารถกดปุ่ม **Edit detail** ในช่องแชทเพื่อแก้ไขค่าต่างๆ และกดปุ่ม **Confirm สร้างกิจกรรม**

#### กฎสำหรับทักษะการสร้างกิจกรรม (Rules for the Activity Creation Skill)
* **ชื่อหรือเจตนาของกิจกรรม (Title/Intent):** เป็นข้อมูลสำคัญเพียงอย่างเดียวที่ไม่ควรกระเดียดคาดเดาหากไม่ชัดเจนจริงๆ
* **วันที่ระบุไม่ครบ:** กำหนดค่าเริ่มต้นเป็นวันนี้ (Today) แต่หากระบุคำว่า "พรุ่งนี้" หรือ "วันถัดไป" ชัดเจน ให้ใช้วันพรุ่งนี้ (Tomorrow)
* **เวลาระบุไม่ครบ:** อนุมานจากชื่อกิจกรรมและบริบททั่วไป เช่น *"ทำการบ้านหลังเลิกเรียน"* กำหนดเป็น 19:00–21:00 น. ส่วนกิจกรรมทั่วไปกำหนดเป็น 19:00–20:00 น.
* **หมวดหมู่ (Category), แท็ก (Tags), การทำซ้ำ (Recurrence), และสถานะตลอดวัน (All-day):** เป็นข้อมูลเสริม ไม่จำเป็นต้องชะลอการสร้างร่างกิจกรรมเพื่อถามข้อมูลเหล่านี้
* **การถามติดตามผล:** ควรถามคำถามสั้นๆ ไม่เกิน 2 คำถาม และสร้างร่างกิจกรรมที่ปลอดภัยให้เสร็จสิ้นภายในข้อความที่ 3 ของผู้ใช้
* **การแก้ไข:** ค่าทุกค่าที่ AI สร้างขึ้นจะต้องแก้ไขได้โดยผู้ใช้ก่อนกดยืนยัน

### ระยะที่ 1 — การสร้างกิจกรรมที่เสถียร (Phase 1 — Stable Activity Creation)
* **เป้าหมาย:** ทำให้อุปกรณ์ผู้ช่วยใน Activity Mode มีความน่าเชื่อถือสูงก่อนเพิ่มความสามารถอื่น
* ย้าย Prompt, Output Schema, ข้อสันนิษฐาน (Assumptions), ตัวอย่าง (Examples), และการตรวจสอบความถูกต้อง (Validation) ไปยังโมดูลทักษะ `activity-creation` ฝั่ง Backend
* คงรูปแบบร่างกิจกรรมที่มีโครงสร้างชัดเจน: ชื่อกิจกรรม, วันเวลาท้องถิ่นเริ่มต้น/สิ้นสุด, สถานะตลอดวัน, หมวดหมู่, แท็ก, การทำซ้ำ, บันทึกเพิ่มเติม, และข้อสันนิษฐาน
* ตรวจสอบความถูกต้องของวัน/เวลาและระยะเวลา (Duration) ฝั่ง Server ก่อนส่งร่างกิจกรรมกลับมา
* มีหน้าต่าง Web Chat แบบเต็มหน้าจอ, ปุ่ม **Edit detail** แบบ Manual, และการกดยืนยันเพียงครั้งเดียวเพื่อสร้างกิจกรรม
* เพิ่มเคสการทดสอบอัตโนมัติสำหรับคำขอภาษาไทยและภาษาอังกฤษ, คำขอที่คลุมเครือ, คำระบุวันที่, กิจกรรมตลอดวัน, และผลลัพธ์ AI ที่ผิดรูปแบบ

**เกณฑ์ความสำเร็จ (Success Criteria):**
* คำขอปกติสามารถสร้างร่างกิจกรรมที่ถูกต้องได้ภายใน 1 ถึง 3 ข้อความ
* ไม่มีคำสั่ง AI ใดสามารถเขียนข้อมูลลงปฏิทินได้ด้วยตัวเอง
* ผลลัพธ์ที่ไม่ถูกต้องจะไม่สามารถเข้าถึง Handler การบันทึกปฏิทินได้

### ระยะที่ 2 — การตระหนักรู้บริบท (Phase 2 — Context Awareness)
* **เป้าหมาย:** ทำให้ข้อเสนอแนะตรงกับตารางเวลาจริงของผู้ใช้
* ส่งเฉพาะบริบทที่จำเป็นไปยังโมเดลตามช่วงวันที่เกี่ยวข้อง: วันเวลาและเขตเวลาท้องถิ่นปัจจุบัน, กิจกรรมรอบๆ เวลาที่เสนอ, กิจกรรมที่ล็อกไว้ (Locked activities), หมวดหมู่และแท็กของผู้ใช้, และช่วงเวลาที่ว่าง
* เพิ่ม Logic แบบ Deterministic ล้อมรอบโมเดล:
  * ตรวจสอบกิจกรรมที่ซ้อนทับกันโดยใช้กฎของ Activity Mode
  * อนุญาตให้มีกิจกรรมซ้อนทับกันได้ไม่เกิน 3 กิจกรรม
  * เสนอช่วงเวลาใกล้เคียงทดแทนเมื่อเกินขีดจำกัด
  * อธิบายข้อขัดแย้งและข้อสันนิษฐานอย่างชัดเจน
  * หลีกเลี่ยงการส่งข้อมูลปฏิทินทั้งหมดไปยังโมเดลโดยไม่จำเป็น

---

### ระยะที่ 3 — ความชอบส่วนบุคคล (Phase 3 — Personal Preferences)
* **เป้าหมาย:** ทำให้คำแนะนำเริ่มต้นรู้สึกเป็นส่วนตัว โดยไม่เปลี่ยนประวัติการสนทนาให้กลายเป็นความจำที่ควบคุมไม่ได้
* จัดเก็บเฉพาะความชอบที่ผู้ใช้ตั้งใจระบุและตรวจสอบได้ เช่น:
```json
{
  "homeworkDefaultStart": "19:00",
  "homeworkDefaultDurationMinutes": 120,
  "exerciseDefaultDurationMinutes": 60,
  "preferredEveningStart": "18:30"
}
```
* เรียนรู้จากค่าที่ผู้ใช้แก้ไขซ้ำๆ ไม่ใช่เรียนรู้โดยอัตโนมัติจากข้อความแชททั้งหมด
* อนุญาตให้ผู้ใช้ดู แก้ไข เปิดใช้งาน หรือลบความชอบที่จัดเก็บไว้ได้ทุกรายการ
* ใช้ความชอบเป็นเพียงค่าเริ่มต้น (Defaults) เท่านั้น ห้ามใช้เป็นกฎบังคับ

---

### ระยะที่ 4 — ทักษะการจัดตารางเวลา (Phase 4 — Scheduling Skill)
* **เป้าหมาย:** วางแผนกิจกรรมมากกว่า 1 รายการโดยไม่เสียการควบคุมของผู้ใช้
* ค้นหาเวลาว่างที่เหมาะสม และเสนอตัวเลือกเวลาที่สมเหตุสมผล 2 ถึง 3 ตัวเลือก
* แบ่งงานขนาดใหญ่ออกเป็นร่างกิจกรรมย่อย เพิ่มช่วงเวลาพัก และหลีกเลี่ยงตารางงานที่หนาแน่นเกินไป
* วางแผนงานรายวันหรือรายสัปดาห์จากรายการภารกิจ
* แสดงตัวอย่าง (Preview) ชุดการเปลี่ยนแปลงที่เสนอทั้งหมดก่อนที่จะสร้างจริง
* ใช้โมเดลที่เก่งกว่าเฉพาะงานวางแผนที่ซับซ้อนจริงๆ และใช้โมเดลต้นทุนต่ำสำหรับร่างกิจกรรมปกติ 1 รายการ

---

### ระยะที่ 5 — ทักษะการจัดการกิจกรรม (Phase 5 — Activity Management Skill)
* หลังจากระบบสร้างกิจกรรมเสถียรแล้ว ให้เพิ่ม Action การจัดการที่ตรวจสอบได้:
  * แก้ไขชื่อ เวลา หมวดหมู่ แท็ก และบันทึก
  * ย้ายหรือคัดลอกกิจกรรม
  * สร้างและปรับแต่งการทำซ้ำ
  * จัดเก็บเข้าคลัง (Archive) และเรียกคืน (Restore)
  * ลบการทำซ้ำเฉพาะรายการ หรือลบทั้งซีรีส์
* ทุก Action ที่มีการเขียนข้อมูลต้องแสดงตัวอย่างที่แม่นยำ เช่น *"ย้าย ‘ประชุมทีม’ จาก 10:00 เป็น 13:00 ใช่ไหม?"*

---

### ระยะที่ 6 — การประเมินและข้อเสนอแนะ (Phase 6 — Evaluation and Feedback)
* รักษากลุ่มวลีทดสอบจากผู้ใช้จริง เช่น *"ทำการบ้านหลังเลิกเรียน"*, *"พรุ่งนี้ประชุมทีมสิบโมงชั่วโมงครึ่ง"*, *"วันศุกร์ไปหาหมอตอนบ่าย"*, *"หาเวลาว่างออกกำลังกายหนึ่งชั่วโมง"*, *"เดือนหน้าทำความสะอาดทุกวันอาทิตย์"*
* ตัววัดผลสำคัญ (Metrics):
  * การทำงานเสร็จสิ้นภายใน 1 ถึง 3 ข้อความ
  * จำนวนการแก้ไขของผู้ใช้ต่อร่างกิจกรรม
  * อัตราผลลัพธ์แบบ Structured Output ที่ถูกต้อง
  * อัตราการเกิดความขัดแย้งของตารางเวลาโดยไม่ตั้งใจ
  * จำนวนการเรียกใช้ AI และต้นทุนต่อการสร้างกิจกรรม 1 รายการ
